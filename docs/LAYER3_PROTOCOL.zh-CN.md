# 第三层事故协议（Layer-3 Incident Protocol）

本系统如何处理词表之外的新情况——以及如何在不腐蚀闸门的前提下修复它们。

## 三层结构

| 层 | 覆盖范围 | 谁来处理 |
| --- | --- | --- |
| **L1 — 已建模词表** | 引擎认识的类型化状态与动作：派发、评审回执、blocker、修复循环、配额耗尽、收敛、环境升级 | 引擎，纯机械 |
| **L2 — 契约内判断** | 歧义、低置信度、状态残留、verdict 标签争议——一切可用既有机制解决的事（reconcile-from-state、逐 pid 派发、只读 codex_cc 交叉验证、advisory 吸收） | orchestrator，自主 |
| **L3 — 词表之外** | 需要**新机制、新词表条目或接线修复**的情况：引擎 fail-closed，或停滞且无任何已建模动作可走 | 外层修复环（见下）——绝不是 orchestrator 单独处理 |

设计意图：**L3 的失败模式是"暂停且可见"，绝不是"带病前进"**。停顿可以恢复；
被伪造的进度不可以。

## 什么算 L3 事故

在活体部署上观察到以下任一情况：

1. **不可归因于调用方错误、且不携带任何模型化修复路径的 fail-closed 拒绝**——
   如工作流真实需要的转移被 `unsupported_requested_state_transition` 拒绝、
   `missing_ao_active_root` / 契约形状不匹配。返回 `allowed_repair_actions`
   的拒绝（如 `unrecognized_governance_dirty` →
   `orchestrator_governance_dirty_review`）属于 L2——执行模型化修复；只有
   该模型化修复路径本身失败时才升级为 L3。
2. **停滞签名**——可证实存在活体工作（worker 完工、PR 已开），但 `list-ready`
   与 `list-gated` 在连续多个 sidecar 巡逻中始终为空。
3. **感知盲区**——canonical 层看不见的运行时状态（agent TUI 对话框等待输入、
   通知腿死亡、hook 每次工具调用都报错）。
4. **基础设施腿故障**——sidecar、notifier、hook 错误跨 tick 重复出现
   （TCC 拒绝、PATH 解析失败、消息发往死会话）。
5. **正常运行期间的任何人工干预。** 如果操作员必须 relay、poke 或手工编辑
   才能让运行继续，这次干预本身就是事故——按定义这是机器本该自己承担的事。

## 角色边界（不可协商）

**orchestrator 负责检测和上报 L3；它永远不修复 L3。**

检测到 L3 签名时，orchestrator：

- 通过 needs-input 通知路径发出结构化报告：尝试了什么、确切的拒绝原因或停滞
  证据、当前 canonical 状态引用（revision、target id、proposal id）；
- 继续推进一切**未被该事故阻塞**的义务；
- **绝不**编辑引擎、契约、自己的 brain 提示词、正常写入车道之外的 canonical
  文件，也绝不放宽、绕过或重新解释任何 fail-closed 闸门。

这条边界是承重墙的原因：被规则挡住就自己扩展规则系统的 agent，就是"自评假门"
反模式——裁判和被裁判塌缩成同一个进程。本协议第一个机制（`historical_closed`
缺调用者绑定）的漏洞之所以被抓出来，正因为修复者在被修复的机器之外。

## 修复环（强制顺序，不许跳步）

1. **活体证据上的根因。** 一字不差地复现失败（确切的拒绝字符串、确切缺失的
   路径）。根因被演示证实（而非推断）之前，不许提修复方案。
2. **书面设计提案。** 带证据的既定事实、提议的机制、考虑过的替代方案、明确的
   问题清单。
3. **设计的独立交叉评审**（codex 或等效的、未参与撰写提案的评审者）。findings
   要么吸收、要么明确反驳——绝不静默丢弃。
4. **类型化实现。** 新能力以显式词表进入，自带 fail-closed 闸门——绝不以放宽
   既有闸门的方式进入。若新车道授予权力，**必须**绑定调用者身份
   （`AO_CALLER_TYPE` + 契约 proof 标准），不信任自报字段。回归测试必须钉死：
   每个既有闸门仍然拒绝它过去拒绝的东西。
5. **实现的独立交叉评审**，基于 diff。
6. **全测试电池与公开安全扫描，全绿。**
7. **活体验证**——原本失败的操作现在成功，且周边循环可证实地动起来。
8. **台账记录**整条链：检测证据、根因、评审 verdict、上线了什么、还剩什么。

## 修复环绝不许越过的硬边界

- 人类专属门保持人类专属（计划文件修改、自动化删除）。L3 修复永远不是
  自动化越过它们的理由。
- 绝不为了适配事故而弯折规则——改机制或扩词表；如果规则本身看起来错了，
  那是 owner 的决定，不是修复步骤。
- 一个事故，一个类型化修复。捆绑式"顺手放宽"是闸门腐蚀的开端。

## 收敛指标

**连续完整周期零人工干预**（种子 → 引擎渲染派发 → worker apply → 评审 →
闭环 → 下一义务）即为收敛。周期内每次人工触碰都要计数、归因、上游化为 L3
缺陷。只减少事故次数而不闭合循环的修复（只加探测器、不加执行器）不是收敛——
是打地鼠，本协议的存在就是为了终结它。
